Ruby「ruby2ßhell」（GHSA-34m4-m9fh-gqp5）— ß の大文字化でヒープオーバーフロー、RCE の恐れ

2026年11月19日 時点（ruby-lang.org 11月18日公表、Veria Labs、Cyber Security News に基づく）。月次レポート：2026年11月レポート。重大度：緊急（Critical）（GitHub Advisory 表記。CVSS は未公表）。

最初に：Ruby を 3.3.14 / 3.4.13 / 4.0.10 に更新し（3.2 以下はサポート中のブランチへ移行）、イメージの再ビルド／アプリの再起動を行ってください。暫定回避策はありません。本ページに攻撃コードは含みません。

かんたん解説 技術概要 影響範囲 確認方法 対策 情報の信頼性 参考情報

非エンジニア／PM 向けの要点

  • 何が起きた？ 一部の古い 1 バイト文字コードで「ß」を大文字にすると「SS」の 2 バイトになりますが、Ruby の空き容量チェックが 1 バイト分しかなく、バッファ境界を 1 バイト超えて書き込みます。
  • どれくらい危険？ Ruby 側は「一部のシナリオで リモートコード実行（RCE） に至る PoC を把握している」としています。Veria Labs によれば Rails と Sinatra（classic）は既定設定で影響を受けます。
  • 対象は？ Ruby 2.4.0〜3.3.13 / 3.4.12 / 4.0.9 を使う全システム。Docker イメージや製品に同梱された Ruby（GitLab、GitHub Enterprise Server、Mastodon、Discourse など）も含みます。
  • PM／管理者がすべきこと： Ruby 利用サービス（サードパーティ製品の同梱 Ruby を含む）の棚卸し、公開面の優先対応、更新と再デプロイの計画。Veria Labs は約 1 週間後（推定 2026-11-26）に PoC を公開予定のため、早期の対応が必要です。

1. 技術概要

  • 本質： ISO-8859 系・Windows-125x 系など一部の 1 バイト文字コードの大文字・小文字変換ループにおける 1 バイトのヒープバッファオーバーフロー（CWE-193）。advisory は ISO-8859-1 と Windows-1252 を例示。出力バッファは入力長＋20 バイトで、ß が 21 個あると 1 バイト溢れます。Ruby 2.4.0 から存在します。
  • 到達するメソッド： upcase、swapcase、downcase(:fold)、casecmp?。UTF-8 は別経路のため影響なし。
  • 識別子： GHSA-34m4-m9fh-gqp5。CVE は申請中（ruby-lang.org・GitHub とも未割り当て）。GitHub は Critical、CVSS は未公表。
  • 同時修正： 文字列変換と Regexp エンジンの 7 件の問題が同時に修正されています（GHSA-34m4-m9fh-gqp5、7x2q-68qv-6p8x、87fm-7w84-j2px、wpqw-5qxg-m68r、3p8q-wmhx-vm2w、7whj-cfh7-xgm4、pvgc-g7gj-pv6h）。攻撃者制御のパターンを compile する際の double free など、RCE の恐れがあるものを含むため、ß 以外も含め Ruby 全体の更新が必要です。
  • 悪用条件： 信頼できない入力文字列が旧 1 バイト文字コードのまま上記変換に渡されること。Rails／Sinatra classic は既定でこれに該当（Veria Labs）。素の Rack は既定では該当しませんが、アプリのコード次第で該当し得ます。

3. 確認方法

実際に稼働している環境の中で Ruby のバージョンを確認してください。ホストの Ruby を更新しても、コンテナやアプライアンスに同梱された Ruby は変わりません。

ruby -v
bundle exec ruby -v
# Docker / Kubernetes
docker ps -q | xargs -I{} sh -c 'docker exec {} ruby -v 2>/dev/null'
kubectl get pods -A -o custom-columns=NS:.metadata.namespace,POD:.metadata.name,IMAGES:.spec.containers[*].image | grep -Ei 'ruby|rails|gitlab|discourse|mastodon'
# リポジトリ内の Ruby バージョン指定
grep -rEn 'ruby ["'"'"']|^ruby ' Gemfile .ruby-version .tool-versions mise.toml Dockerfile 2>/dev/null

自作コードで、旧文字コード（ISO-8859-x、Windows-125x へ force_encoding／encode）の信頼できない文字列に upcase／swapcase／downcase(:fold)／casecmp? を使っていないかも確認してください。

4. 恒久対策と暫定対策

方法 1：修正版 Ruby へ更新（推奨・唯一の恒久対策）

  1. 使用ブランチ別の更新先： 3.3.x → 3.3.14、3.4.x → 3.4.13、4.0.x → 4.0.10。Ruby 3.2 以下は EOL で修正版がないため、3.3 / 3.4 / 4.0 への移行を計画してください（アプリが動作する範囲で、より長くサポートされるブランチを選択）。
  2. リポジトリ内のバージョン指定を更新： .ruby-version、.tool-versions、mise.toml、Gemfile の ruby "x.y.z"、Dockerfile、CI 設定。ビルドと開発で同じ版を使い、Gemfile.lock も一緒にコミットします。
  3. 新しい Ruby をインストール（下表参照）し、bundle install とテストを実行。
  4. デプロイと再起動： 稼働中の Ruby プロセスは再起動するまで旧バイナリのままです（Puma、Unicorn、Passenger、Sidekiq、cron/rake ワーカーなど）。コンテナは旧コンテナの再起動ではなく、イメージを再ビルドしてロールアウトします。
  5. 確認： ビルドマシンではなく、実際の稼働環境（コンテナ／Pod／dyno）の内部で ruby -v を実行。対応済みサービスを記録します。
  6. Ruby を同梱するサードパーティ製品（GitLab、GitHub Enterprise Server、Mastodon、Discourse、OpenProject、Chatwoot など）：ベンダーのリリースでのみ更新可能で、ホストの Ruby を更新しても効果はありません。ベンダーの advisory を確認し、Ruby 3.3.14 / 3.4.13 / 4.0.10 を含む版を適用後、内部の Ruby バージョンを再確認します。

優先順位： (1) インターネット公開かつ未認証でユーザー文字列を処理するサービス（Rails/Sinatra の API、フォーム、アップロード、Webhook）、(2) インターネット公開のサードパーティ製セルフホスト製品（GitLab、GHES、Discourse など）、(3) 社内サービス、(4) CI ツール・バッチジョブ。PoC が約 2026-11-26 に公開される予定のため、(1) と (2) はそれまでに完了させてください。

方法 2：暫定対策（すぐに更新できない場合）

重要： ruby-lang.org と Veria Labs は公式な回避策を示していません。以下はリスク低減のための措置であり、更新の代替にはなりません。脆弱性を完全に防げることを確認した情報源もありません。

  1. 公開範囲の縮小： 公開が必須でないサービスは、Ingress／ALB で VPN・IP 許可リスト・SSO の背後に置く。不要な匿名の文字列入力エンドポイントは一時的に停止。
  2. 大文字・小文字変換の前に UTF-8 へ正規化： 問題は旧 1 バイト文字コードの経路にあり、UTF-8 は別経路で影響を受けません。自作コードでは、upcase / swapcase / downcase(:fold) / casecmp? の前に信頼できない入力を UTF-8 に変換（例：str.encode("UTF-8", invalid: :replace, undef: :replace)）するか、旧文字コードの入力を拒否します。ただし対象は自作コードのみで、gem やフレームワーク内部は防げません（Veria Labs によれば Rails と Sinatra classic は既定で影響）。
  3. 自作コードの棚卸し： 上記メソッドの呼び出し箇所と、ISO-8859-x／Windows-125x への force_encoding／encode の使用箇所を検索。 
    grep -rnE 'upcase|swapcase|downcase\(:fold\)|casecmp\?' app lib 2>/dev/null
grep -rnE 'force_encoding|ISO-8859|Windows-125' app lib config 2>/dev/null
  4. 監視： Ruby プロセスの異常終了ログ（segfault、"[BUG]"、ワーカーの kill と再起動の繰り返し）、テキストパラメータ中の ß の大量出現や異常な繰り返しを監視し、運用チームへ通知。
  5. 迅速に更新できる準備： ステージングで新しい Ruby イメージを試験ビルドしてテストし、ロールバック手順とメンテナンス枠を事前に確保。
  6. WAF を代替とみなさない： ß は氏名・住所など正当なデータにも含まれ、公開済みの攻撃シグネチャもありません。

5. 情報の信頼性

  • CVE： ruby-lang.org と GitHub は未割り当てとしています。二次情報の一部が CVE-2026-132825 に言及していますが、レコードを確認できていないため主要な参照には使わないでください。
  • 悪用状況： Ruby は RCE の PoC を把握としていますが非公開。Veria Labs は約 1 週間後（推定 2026-11-26）に公開予定。実環境での悪用を報告する情報源はありません。
  • 混同注意： CVE-2026-66066（KindaRails2Shell、Rails Active Storage）および CVE-2026-97229（GitLab CI/CD の正規表現、悪用報告あり）は別の脆弱性で、ruby2ßhell ではありません。
  • 未確認： GitLab、GHES、Chatwoot の修正版、Docker 公式イメージ、Heroku、AWS の対応、影響を受ける文字コードの完全な一覧、CVSS。Mastodon、OpenProject、Discourse の情報は Veria Labs のみが出典です。
