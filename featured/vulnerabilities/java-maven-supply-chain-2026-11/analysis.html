Java Malware Today — Chuỗi cung ứng Maven & Gradle & Cách kiểm tra build

Công bố: 2026-11-25 · Cập nhật: 2026-11-26 · Bản tin tháng: Báo cáo tháng 11/2026 · Mức độ: Trung bình (Supply Chain) (Nguồn: Safeguard.sh, GitHub Advisories, OSV, OpenSSF).

Đọc trước: Tính đến 25-11-2026 (18:10 UTC), các feed công khai (GitHub Advisory Database, OSV, OpenSSF) chỉ ghi nhận 2 gói Maven độc hại (đều từ 2025). Tuy nhiên, số lượng ít không đồng nghĩa build Java an toàn: mã độc thường ẩn trong Gradle/Maven plugin, annotation processor và dependency confusion. Hãy chạy osv-scanner scan source -r ., kiểm tra cây phụ thuộc/cache và bật xác minh chữ ký/checksum. Trang này không chứa mã khai thác.

TL;DR (dễ hiểu)

  • Là gì? Báo cáo tổng hợp từ Safeguard.sh (25-11-2026) đối chiếu các cơ sở dữ liệu mã độc công khai cho hệ sinh thái Java (Maven Central / Gradle).
  • Nguy hiểm thế nào? Dù chỉ có 2 gói Maven bị gắn cờ công khai, máy quét CVE thông thường bỏ sót gói độc hại (vì chúng dùng mã MAL- chứ không có CVE). Ngoài ra, plugin Gradle/Maven có thể chạy mã độc ngay lúc biên dịch (./gradlew help cũng đã kích hoạt plugin).
  • Dự án có bị ảnh hưởng không? Các dự án Java / Spring Boot dùng Maven hoặc Gradle cần kiểm tra xem có vô tình kéo gói typosquat (io.github.leetcrunch:scribejava-core) hoặc gói npm nhiễm sâu Sha1-Hulud qua mvnpm (org.mvnpm:posthog-node) hay không, đồng thời rà soát cấu hình repository nội bộ.
  • PM & Tech Lead cần làm gì? Yêu cầu đội Java chạy bộ lệnh kiểm tra trong mục 3 trên repo và CI runner, bật khóa phiên bản (gradle.lockfile) và gom tải gói qua một repository manager nội bộ duy nhất.

1. Tóm tắt kỹ thuật

  • Vì sao số lượng advisory thấp? OpenSSF malicious-packages chỉ ghi nhận các gói được báo cáo và duyệt. Mã độc trong Gradle plugin, repo nội bộ hoặc script build ít khi có mã MAL- công khai.
  • Thực thi mã ở pha build: Maven plugin, script build.gradle(.kts) / settings.gradle(.kts) (chạy ngay từ pha cấu hình, kể cả khi gọi ./gradlew help), annotation processor trên JDK < 23 (hoặc có -proc:full), và mvn test / ./gradlew test đều chạy mã với quyền của user build.
  • Thứ tự repository & POM bên thứ ba: Maven truy vấn repo theo thứ tự settings.xml → local POM → parent POM → super POM → POM của dependency. Một dependency có thể tự khai báo thêm repo ngoài; trong Gradle, thứ tự khai báo repositories quyết định nơi tải gói nếu không dùng exclusiveContent.

3. Kiểm tra nhanh trên repo & CI runner

1. Tìm kiếm 2 tọa độ độc hại trong cây phụ thuộc

# Maven
mvn -q dependency:tree -Dincludes=io.github.leetcrunch
mvn -q dependency:tree -Dincludes=org.mvnpm:posthog-node

# Gradle (kiểm tra cả runtimeClasspath và buildEnvironment nơi chứa plugin)
./gradlew dependencies --configuration runtimeClasspath
./gradlew dependencyInsight --dependency scribejava-core --configuration runtimeClasspath
./gradlew buildEnvironment

2. Kiểm tra cache cục bộ & CI runner

ls ~/.m2/repository/io/github/leetcrunch 2>/dev/null
ls ~/.m2/repository/org/mvnpm/posthog-node/4.18.1 2>/dev/null
ls ~/.gradle/caches/modules-2/files-2.1 | grep -E '^(io\.github\.leetcrunch|org\.mvnpm)$'

3. Quét toàn bộ dự án bằng OSV-Scanner & kiểm tra cấu hình tin cậy

# Quét lockfile, manifest, SBOM đối chiếu cả bản ghi MAL- trên OSV
osv-scanner scan source -r .

# Xem thứ tự repository thực tế của Maven & bật strict checksum / PGP
mvn help:effective-settings
mvn -C verify
mvn org.simplify4u.plugins:pgpverify-maven-plugin:check

# Gradle: tạo tệp xác minh chữ ký PGP + SHA256 (chạy từ trạng thái sạch, review trước khi commit)
./gradlew --write-verification-metadata pgp,sha256 --export-keys help

4. Khắc phục & Phòng ngừa dài hạn

  • Một cửa vào duy nhất: Định tuyến toàn bộ tải gói qua một repository manager nội bộ với mirrorOf *; xóa bỏ các thẻ <repositories> tự phát trong pom.xml.
  • Ghim groupId nội bộ & đăng ký namespace: Dùng exclusiveContent trong Gradle cho các groupId nội bộ và đăng ký xác minh namespace tương ứng trên Maven Central để tránh bị chiếm dụng.
  • Khóa phiên bản & rà soát file build như code production: Tránh version động/dải mở; bật ./gradlew dependencies --write-locks (gradle.lockfile); tách biệt token publish/deploy khỏi các CI job build PR; kiểm tra distributionSha256Sum trong gradle-wrapper.properties.

5. Độ tin cậy & lưu ý

  • Đối chiếu dữ liệu trực tiếp: Số liệu được tổng hợp từ bài viết của Safeguard.sh (25-11-2026, truy vấn API lúc 18:10 UTC) và khớp với 2 bản ghi công khai trên OSV (MAL-2025-2552 công bố 19-03-2025; MAL-2025-191470 công bố 26-11-2025) cùng GitHub Advisory Database (import 13-07-2026).
  • Phạm vi giới hạn: Chưa ghi nhận mã độc Maven mới phát sinh trong năm 2026 trên 3 feed công khai nói trên; tuy nhiên feed chỉ phản ánh những gì đã được báo cáo, không bao gồm gói độc hại trong repo riêng hoặc plugin chưa bị phát hiện.
