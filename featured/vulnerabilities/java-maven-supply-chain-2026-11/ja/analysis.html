Java（Maven / Gradle）サプライチェーン — OAuth/GitHub トークン窃取マルウェア（MAL-2025-2552・MAL-2025-191470）とビルド時コード実行リスク

公開日：2026-11-25 · 更新：2026-11-26 · 月次レポート：2026年11月レポート · 重大度：中（Supply Chain）（出典：Safeguard.sh、GitHub Advisories、OSV、OpenSSF）。

先にお読みください： 2026年11月25日（18:10 UTC）時点で、公開フィード（GitHub Advisory Database、OSV、OpenSSF）に登録されている悪性 Maven パッケージは2件のみ（いずれも2025年発生）です。しかし、件数が少ない＝安全ではありません。実際の脅威は Gradle/Maven プラグイン、アノテーションプロセッサ、依存関係混乱（Dependency Confusion）に潜みます。osv-scanner scan source -r . の実行、依存木・キャッシュ点検、チェックサム／署名検証を有効化してください。本ページには攻撃コードは含まれません。

TL;DR（かんたん解説）

  • 何か？ Safeguard.sh（2026年11月25日）による、Java（Maven Central / Gradle）エコシステム向けの公開マルウェアフィード調査と実践的なビルド点検ガイドです。
  • 何が危険か？ 公開リスト上の悪性 Maven パッケージは2件ですが、従来の CVE スキャナは MAL- ID を持つ悪性パッケージを見逃します。また Gradle プラグインは ./gradlew help を実行しただけで設定フェーズにコードが動きます。
  • 影響を受けるか？ Maven / Gradle を使う Java / Spring Boot プロジェクトは、タイポスクワット（io.github.leetcrunch:scribejava-core）や mvnpm 経由の Sha1-Hulud ワーム感染版（org.mvnpm:posthog-node 4.18.1）が紛れ込んでいないか、また内部リポジトリ設定を確認する必要があります。
  • PM・リーダーがすべきこと： Java 開発チームにセクション3の点検コマンドを全リポジトリと CI ランナーで実行させ、依存ロック（gradle.lockfile）と単一リポジトリマネージャ経由への統一を指示してください。

1. 技術概要

  • 公開件数が少ない背景： OpenSSF malicious-packages は報告・審査済みの記録のみを収録します。Gradle プラグインや社内リポジトリ、ビルドスクリプト内の不正コードは MAL- 化されない場合が多くあります。
  • ビルド時のコード実行： Maven プラグイン、build.gradle(.kts) / settings.gradle(.kts)（./gradlew help でも設定フェーズでプラグインを実行）、JDK 23 未満（または -proc:full 指定時）のアノテーションプロセッサ、テスト実行はいずれもビルドユーザー権限で動作します。
  • リポジトリ解決順序： Maven は settings.xml → ローカル POM → 親 POM → スーパー POM → 依存先 POM の順に参照するため、外部依存の POM が新たなリポジトリを追加し得ます。Gradle でも exclusiveContent なしでは宣言順に左右されます。

3. 迅速点検（リポジトリ & CI ランナー）

1. 依存ツリー内の既知悪性座標を検索

# Maven
mvn -q dependency:tree -Dincludes=io.github.leetcrunch
mvn -q dependency:tree -Dincludes=org.mvnpm:posthog-node

# Gradle（プラグインを含む buildEnvironment も確認）
./gradlew dependencies --configuration runtimeClasspath
./gradlew dependencyInsight --dependency scribejava-core --configuration runtimeClasspath
./gradlew buildEnvironment

2. ローカルキャッシュ・CI ランナーキャッシュを確認

ls ~/.m2/repository/io/github/leetcrunch 2>/dev/null
ls ~/.m2/repository/org/mvnpm/posthog-node/4.18.1 2>/dev/null
ls ~/.gradle/caches/modules-2/files-2.1 | grep -E '^(io\.github\.leetcrunch|org\.mvnpm)$'

3. OSV-Scanner 走査と信頼設定の確認

# OSV の MAL- 記録を含めて一括スキャン
osv-scanner scan source -r .

# Maven の実効リポジトリ順序と厳格チェックサム・PGP 検証
mvn help:effective-settings
mvn -C verify
mvn org.simplify4u.plugins:pgpverify-maven-plugin:check

# Gradle：クリーンな状態から PGP + SHA256 検証ファイルを生成（コミット前に要レビュー）
./gradlew --write-verification-metadata pgp,sha256 --export-keys help

4. 対策と恒久的なビルド強化

  • 単一ゲートウェイ化： すべての取得を社内リポジトリマネージャ経由（mirrorOf *）に統一し、pom.xml 内の野良 <repositories> 定義を排除します。
  • 内部 groupId の保護： Gradle の exclusiveContent で内部グループを社内リポジトリに固定し、Maven Central 上の対応名前空間も事前登録して乗っ取りを防ぎます。
  • バージョン固定と PR レビュー強化： ./gradlew dependencies --write-locks（gradle.lockfile）で版を固定し、PR 用 CI ジョブから公開・デプロイ鍵を分離、gradle-wrapper.properties の distributionSha256Sum を設定します。

5. 情報の信頼性と注意点

  • 一次情報との照合： Safeguard.sh（2026年11月25日 18:10 UTC の API 集計）の記述を、OSV（MAL-2025-2552：2025-03-19 初出、MAL-2025-191470：2025-11-26 初出）および GitHub Advisory Database（2026-07-13 取込）と照合しました。
  • 範囲の制約： 調査時点で2026年新規の公開 Maven マルウェア記録はありませんが、非公開リポジトリや未報告のプラグイン侵害はフィードに現れないため、上記の予防策と組み合わせた運用が必要です。
