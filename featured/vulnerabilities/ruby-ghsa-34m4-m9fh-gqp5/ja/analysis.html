Ruby「ruby2ßhell」（CVE-2026-132825 / GHSA-34m4-m9fh-gqp5）— 図解サマリー

公開日：2026-11-18 · 2026年11月25日 時点 · 月次レポート：2026年11月レポート · 重大度：Critical · CVSS v3.1：9.8（RH）/ 8.1（AL）/ 7.4（MITRE）。

今すぐ対応：Ruby を 3.3.14 / 3.4.13 / 4.0.10 へ更新（または GitLab・GHES・Docker・各 Linux ディストリ・クラウドの修正版を適用）し、イメージ再ビルドと再起動を実施してください。本ページは要点のみを解説し、攻撃コードは含みません。

TL;DR（かんたん解説）

  • 何が起きた？ 古い 1 バイト文字コードで「ß」を大文字（"SS"）にする際、Ruby のバッファ計算が不足して 1 バイト隣へ溢れ、プロセス停止やリモートコード実行（RCE）につながる恐れがあります。
  • 誰が対象？ Ruby 2.4.0〜4.0.9 を使う環境（Rails、Sinatra classic、および GitLab・GHES・Mastodon・Discourse など同梱製品を含む）。
  • 修正版はある？ はい。2026-11-25 時点で、Ruby 本体・Docker Hub・主要 Linux ディストリ・クラウド（AWS/Heroku/Render）・主要製品すべてに修正版が出ています。
  • 今やるべきことは？ Veria Labs の RCE PoC 公開予定（11/25 以降）に先立ち、インターネット公開中のサービスから優先して更新と稼働確認を完了してください。

1. 脆弱性の仕組み（図解）

  • 対象のメソッドと文字コード： 14 種の旧 1 バイト文字コード（ISO-8859-1/2/3/4/9/10/13/14/15/16 と Windows-1250/1252/1254/1257）での upcase / swapcase / downcase(:fold) / casecmp?（Symbol 含む）のみ該当。UTF-8 は対象外です。
  • 同時修正の他 6 件： 11/18 の修正版では Regexp 系の Critical 2 件や整数溢れ（GHSA-87fm-7w84-j2px）を含む計 7 件が一括修正されているため、Ruby 本体の更新が必要です。
  • 評価の補足： CVSS v3.1 は Red Hat 9.8、Amazon Linux 8.1、MITRE/NVD 7.4。watchTowr は「実環境で安定した RCE に持ち込む条件は厳しく、一般にはクラッシュ（DoS）になりやすい」と分析しています。

4. 恒久対策・暫定対策

方法 1：Ruby 本体・同梱製品のアップグレード（推奨）

  1. インターネット公開面を最優先し Ruby を更新：.ruby-version・Gemfile・Dockerfile やビルドツール（ruby-build v20261119、ruby/setup-ruby）を 3.3.14・3.4.13・4.0.10 へ更新します。3.2 以下（EOL）は 3.3 / 3.4 / 4.0 へ移行するか、Linux ディストリ修正版（Debian DSA-6644-1 / DLA-4926-1、Ubuntu USN-9176-1、RHEL 8/9/10 RHSA、AL2023 ALAS2023-2026-3509..3511）を適用します： 
    # Dockerfile：修正済み公式イメージを指定
# FROM ruby:3.4.13-slim   （または 3.3.14 / 4.0.10）

# rbenv / ruby-build（ruby-build v20261119 以降が必要）
rbenv install 3.4.13 && rbenv local 3.4.13

# Linux ディストリ（Debian / Ubuntu / AL2023）
sudo apt update && sudo apt upgrade -y ruby*
# または：sudo dnf update -y ruby*
  2. セルフホスト製品・Cloud/PaaS の更新：GitLab（19.6.1 / 19.5.8 / 19.4.10）、GHES（3.22.6 / 3.21.11 / 3.20.13 / 3.19.17）、Mastodon（4.7.6 / 4.6.12 / 4.5.22 / 4.4.29）、OpenProject（17.9.8 / 17.8.3）、Chatwoot（4.20.1）を修正版へ更新します。Discourse はベースイメージ 2.0.20261119-0203 を取り込むため CLI での再ビルドが必須です： 
    # Discourse：CLI 再ビルドが必須
cd /var/discourse
git pull
./launcher rebuild app
  3. イメージ再ビルド・再デプロイ・ワーカー再起動：稼働中の Puma / Unicorn / Sidekiq プロセスは再起動まで旧 Ruby バイナリを保持します。AWS Lambda（コンテナー版）は再ビルド＆再デプロイ、Heroku/Render は再デプロイで既定 3.4.13 を反映します（AWS EB は 4.15.4）： 
    docker build --pull --no-cache -t <ruby-app>:<tag> .
kubectl rollout restart deployment/<deployment-name> -n <namespace>
# VM 上の場合：
sudo systemctl restart puma sidekiq
  4. デプロイ後の実バージョン確認：コンテナー／Pod 内や Discourse 内で ruby -v を実行し、更新が反映されていることを確認します： 
    bundle exec ruby -v
docker ps -q | xargs -I{} sh -c 'docker exec {} ruby -v 2>/dev/null'
./launcher enter app -c 'cat /VERSION && ruby -v'   # Discourse：2.0.20261119 以降

方法 2：暫定対策・多層防御（即時更新が困難な場合）

ruby-lang.org および各製品ベンダーの公式対策は、修正版 Ruby／ベンダー版への更新です。Cloudflare と CrowdSec は CVE-2026-132825 向け WAF ルールを提供しています。以下のアクセス制限・旧 1 バイト文字コード遮断・ログ監視は PiraGo による暫定の多層防御推奨であり、Ruby 本体の更新に代わるものではありません。

  1. 公開範囲の制限：必須でない社内サービス（Rails/Sinatra、GitLab、GHES、OpenProject 等）は VPN・IP 許可リスト・SSO の背後に退避します。
  2. WAF による暫定防御：Cloudflare（Free/Managed 双方で利用可）と CrowdSec が提供する CVE-2026-132825 向け遮断ルールを有効化します。
  3. リバースプロキシでの旧 1 バイト文字コード遮断（PiraGo 多層防御）：本脆弱性は 14 種の旧 1 バイト文字コード（ISO-8859-1/2/3/4/9/10/13/14/15/16、Windows-1250/1252/1254/1257）でのみ発生し、UTF-8 は影響を受けません。更新までの間、プロキシ側で旧 1 バイト charset を指定するリクエストを遮断します： 
    # NGINX（PiraGo 多層防御）：Content-Type の旧 1 バイト charset を拒否
if ($http_content_type ~* "charset\s*=\s*(iso-8859-|windows-125)") {
    return 400;
}
  4. ログ点検（Threat Hunting）：アプリ／OS ログで異常終了（segfault、SIGSEGV、[BUG]）や Puma/Unicorn/Sidekiq ワーカーの連続再起動がないか確認し、_method や X-HTTP-Method-Override と ISO-8859-* / Windows-125* を組み合わせた不審リクエストを監視します。
