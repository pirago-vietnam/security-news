Laravel Framework GHSA-8h64-cpq2-9h2g — TransformsRequest の JSON 処理による DoS

公開日：2026-11-23（CVE 未採番）· 2026年11月27日 時点。月次レポート：2026年11月レポート。重大度：高（High）（CVSS v3.1 7.5 · AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H）。

最初にお読みください：laravel/framework を 12.74.0+ または 13.38.0+（メモリ最適化まで含む 13.39.0+ を推奨）へ更新してください。Laravel 11.x はセキュリティサポート終了（EOL：2026-03-12）のため修正版は提供されません。本ページに攻撃コードは含みません。

TL;DR 1. 技術メカニズム 2. 影響範囲 3. 確認コマンド 4. 恒久対策・暫定対策 5. 参考情報

TL;DR（かんたん解説）

  • 脆弱性の内容：Laravel の標準ミドルウェア TransformsRequest（TrimStrings・ConvertEmptyStringsToNull の親クラス）の不具合で、ルーティングや認証より前に全リクエストで実行されます。
  • 危険度：未認証の攻撃者が通常サイズ（約 590 KB）の JSON に長い 1 キーと大きな配列を含めて数件並列送信するだけで、数十 GB のメモリ確保と約 30 秒/件の CPU 消費を引き起こし、PHP ワーカーを枯渇させてサービス停止（DoS）に至ります。
  • 対象システム：12.x < 12.74.0、13.x < 13.38.0、および 11.x・10.x 以前（EOL で未修正）のすべての Laravel アプリ。
  • PM／テックリードの対応：composer.lock を確認し、12.74.0+ または 13.39.0+（最低 13.38.0）へ更新してください。11.x はメジャーアップグレード計画が必要です。

1. 概要と技術メカニズム

  • 根本原因：再帰メソッド cleanArray(array $data, $keyPrefix = '') が各要素で $keyPrefix.$key を構築します。PR #62582 の試算では、約 590 KB の JSON（約 295 KB のキー 1 つ＋約 14.7 万要素）で約 43 GB の文字列確保と約 30 秒の CPU 消費が発生します。また未変更配列の毎回代入による copy-on-write 複製や、TrimStrings::transform() が is_string() 前に Str::is() を呼ぶ点も負荷を増大させていました。
  • 修正内容：$maxKeyBytes = 20 * 1024 * 1024（20 MB、Octane 対応のため handle() 開始時に $keyBytes = 0 にリセット）を超過した時点で PostTooLargeException（HTTP 413）を送出します。

4. 恒久対策・暫定対策

  • 恒久対策（推奨）：laravel/framework を 12.74.0+ または 13.39.0+（最低 13.38.0）へ更新します。Laravel Octane 環境ではデプロイ後にワーカーを再起動してください。
  • 暫定対策：公式の回避策はありません。TrimStrings / ConvertEmptyStringsToNull を無効化すると入力正規化が変わるため推奨されません。リバースプロキシ／WAF でリクエストボディサイズを制限しつつ、早急にフレームワークを更新してください。
