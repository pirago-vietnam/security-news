国内相次ぐ情報流出（2026年11月20〜21日）— タワーレコード、ピーチ・アビエーション（ユミルリンク）、インフキュリオン Wallet Station / Payどん

発生・公開日：2026-11-20（ピーチ、インフキュリオン）／2026-11-21（タワーレコード） · 2026-11-23 時点 · 出典：各社の公表と国内報道 · 状況：進行中。月次レポート：2026年11月レポート。

TL;DR（要点）：2026年11月20〜21日の2日間に、国内3組織が不正アクセスと顧客情報流出の恐れを公表しました。

  • タワーレコード オンライン：最大約1,100万件（メールアドレス、パスワードのハッシュ値、氏名、住所、電話番号など）。クレジットカード情報は含まれず、オンラインストアは停止中。
  • ピーチ・アビエーション：約900万件（氏名、生年月日、住所、電話番号、メール、旅程）。原因はピーチ自社ではなくメール配信事業者ユミルリンク（Cuenote FC）。カード・パスポート情報は含まれません。
  • インフキュリオン Wallet Station / Payどん：約25万件が流出の恐れ、Payどんの全サービスが停止。
  • 共通点：顧客データが外部事業者・共通基盤にあり、1か所の弱点が複数ブランドに波及します。
  • やること：なりすましメール・SMS・電話への警戒、パスワード使い回しの変更、自社の委託先（メール配信・決済）の棚卸し。

2. 原因・メカニズム

2.1 ピーチ・アビエーション ← ユミルリンク Cuenote FC（事業者が説明）

  • ユミルリンク第3報（11/11、ScanNetSecurity 経由）：プログラムの脆弱性を突いてサポート／QA担当者の認証情報を取得し、他システムで試行。手法1：サーバーにマルウェアを設置し、基幹DBからデータを抽出、管理ネットワーク内で横展開。手法2：ログイン中ユーザーのセッションを窃取し、標準のCSV出力機能を利用。同社はランサムウェアではないと説明、侵入経路・全容は調査中。
  • Cuenote FC 全体：10/26 の第2報では最大 51,628,280 件・49システム（81システムでアクセス痕跡）、第3報で Cuenote FC 47,864,147 件、Cuenote BASE 190 件（社名・氏名・電話・メール）に修正。他のユミルリンク顧客も影響（例：NTTPCコミュニケーションズ 60,929件、11/2 公表）。
  • 日付の食い違い：ユミルリンクのアクセス検知は 10/16、ピーチの公表では委託先への侵入は 10/18。ピーチ公表（JP）は 10/18 のみ記載し、影響範囲の確定は 11/6 とあります。10/16 は ScanNetSecurity の要約にのみ見られ、差の理由は未解明です。
  • 別件との区別：2026年10月7日の予約メール委託先 IDCF Cloud へのランサムウェア被害（ピーチ 10/9 公表、当時は流出未確認）は別の事案です。

2.2 タワーレコード オンライン

  • 公表は「外部からの不正アクセス」のみ。侵入経路・悪用された脆弱性は未公表。ログイン情報にハッシュ値が含まれることから、アカウントDBに到達されたとみられます。

2.3 インフキュリオン Wallet Station / Payどん

  • インフキュリオンは 11/19 に第三者の不正アクセスを確認。Payどんは「緊急の脆弱性パッチを適用し、アクセス経路を遮断」と説明しますが、脆弱性や侵入点は非公表です。
  • Payどんは銀行登録の電話番号へのSMS認証を採用しており、流出データだけでは直ちに取引できないとしています（Payどんの説明、独立検証なし）。
  • Wallet Station は複数企業に提供されており、「影響のある」提供先への提供を一時停止（社名・件数は非公表）。AEON Pay・HAPPAY への影響を伝える報道・ブログもありますが、公式の裏付けなし、未検証です。
  • 2026年10月28日にはPayどんのメール配信委託先で別件の事案があり、また 11/18 の Notion AI／Fireworks AI 関連の開示は同社システムへの侵害ではないと説明されています。いずれも別件です。

4. 影響・二次リスク

  • なりすまし（フィッシング／ビッシング）：氏名・電話・メール・生年月日・旅程（ピーチ）が揃うと、航空会社、タワーレコード、Payどん／銀行、インフキュリオンを装った精巧な詐欺が可能。3社とも注意喚起しています。
  • パスワードリスト型攻撃（タワー、Payどん）：ハッシュ（タワー）やパスワード（Payどん）が解析・流用されると、使い回し先が狙われます。
  • サービス停止：タワー通販とPayどんが停止し、Payどんでの地域決済・ポイント利用は復旧まで不可。
  • サプライチェーンリスク：Cuenote FC は多数の組織が利用し、1社の侵害で複数ブランド・数千万件に波及。Wallet Station も同様です。
  • 法令対応：ピーチは個人情報保護委員会（PPC）へ報告済み。タワー、インフキュリオンへの行政対応は 11/23 時点で確認できていません。

5. PiraGo への推奨事項

  1. 委託先の棚卸しと評価（特にメール配信・ウォレット／決済）：
    • PiraGo／顧客の顧客データを保持するベンダーを一覧化し、ユミルリンク Cuenote FC、Wallet Station 等の利用有無を確認、該当時はベンダーへ影響確認を行う。
    • 契約に、事故報告の期限、監査権、利用終了後のデータ削除、データ範囲の最小化を明記する。
  2. 外部へ渡すデータの最小化と削除：
    • 配信リストはメール＋匿名IDに限定し、生年月日・住所・旅程などは必須でなければ連携しない。
    • 過去キャンペーンのリストや退会者データを定期的に削除・分離する。
  3. ユーザーアカウント保護：
    • Argon2id／bcrypt＋ソルトでハッシュ化し、復元可能な形で保存しない。
    • MFA／パスキー、/login のレート制限・ボット対策、漏えいパスワード検査（HIBP k-Anonymity）、一括パスワード再設定の準備。
    • 金融操作では、独立した第2要素（PayどんのSMS認証のような）がデータ流出時の重要な歯止めになる。
  4. インシデント対応：
    • 緊急停止スイッチと封じ込めSLAを定める（タワー・Payどんは当日停止、MUJIの8日間未封じ込めと対比）。
    • 顧客通知テンプレート、問い合わせ窓口、フィッシング見分け方の案内を事前準備する。
  5. 利用者・社内への周知：
    • タワーレコード、ピーチ、Payどん／銀行、インフキュリオン、ユミルリンクを名乗る予期しないメール・SMS・電話のリンクや添付を開かず、ID・パスワード・認証コード・口座情報を入力しない。
    • タワー／Payどんのパスワード（変更可能なら）と、同じパスワードを使う他サービスを変更する（一般的な推奨であり、公式に確認された指示ではない）。
    • 銀行明細・取引の不審な動きを確認。Payどん窓口：デジタルサポートプラザ（鹿児島銀行）0120-947-230、平日 9:00〜17:00。
