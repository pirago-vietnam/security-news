1Password セキュリティインシデント（2026年11月）— 従業員 GitHub 侵害とバックエンドへの悪性コード投入

発生・公開日：2026-11-25（検知・調査開始 2026-11-19） · 2026-11-26 時点 · 出典：1Password 公式ブログ、TechCrunch、The Hacker News、BleepingComputer · 状況：封じ込め・クリーン版復旧済み、顧客 Vault への影響なし。月次レポート：2026年11月レポート。

TL;DR（エンジニア・PM向け要約）：

  • 何が起きたか：2026年11月19日、1Password は攻撃者が従業員の企業 GitHub アカウントに侵入し、非公開リポジトリ・CI/CD にアクセスしてバックエンドへ悪性コードを投入し、一部顧客の管理レコードを取得した事案を検知しました（11月25日公表）。
  • 流出した情報（一部顧客のみ）：氏名、ログイン用メールアドレス、アカウント/ユーザー ID、作成日時・最終ログイン日時、公開鍵、SRP パラメータ、招待・プロビジョニング（SCIM）・アカウント復旧メール内のトークン、非機密の内部メタデータ。また非公開ソースコードおよび CI/CD インフラ関連の内部シークレットもアクセスを受けました。
  • 安全だった情報：顧客の Vault・保存されたパスワード/アイテム・Vault 暗号鍵・マスターパスワード・Secret Key・復旧鍵 は一切アクセスされていません（クライアント側暗号化・ゼロ知識設計）。露出したトークンによるアカウント乗っ取りも確認されていません。
  • 利用者がすべきこと：マスターパスワードや Secret Key の変更は不要です。1Password からの公式通知の有無を確認し、標的型フィッシング（偽の招待・復旧メールや SMS・電話）に警戒してください。

1. 攻撃チェーン（Attack Chain）

2026年11月25日の公式発表によると、攻撃者は Vault の暗号機構を破ったのではなく、開発基盤（従業員 GitHub アカウント → CI/CD → バックエンド）を経由して管理レコードへ到達しました。

2. 流出情報と安全だった情報

対象データ状態技術的補足
氏名・メール・ID・ログイン時刻 流出（一部顧客） アカウント管理用メタデータ。メールアドレス露出により 1Password を騙る標的型フィッシングのリスクが高まります。
SRP パラメータ・公開鍵 流出（単体悪用不可） 公開鍵は設計上公開情報であり、SRP もパスワードを送信しない認証方式のため、これら単体では復号やログインはできません。
招待・プロビジョニング・復旧トークン 流出（二要素が必要） SSO ログインまたはメール確認コードが必要なため単体では悪用不可。有効なトークン状態にあった少数のユーザーには個別通知済み。
Vault・マスターパスワード・Secret Key 完全に安全 クライアント側暗号化によりサーバーは復号鍵を持たないため、バックエンド侵害でも Vault 内容は閲覧・復号できません。

3. 経緯と 1Password の対処

  • 2026-11-19 以前：従業員の企業 GitHub アカウントが侵害された正確な日時・手法は非公開。
  • 2026-11-19：1Password が異常を検知し、従業員 GitHub アカウントへの不正アクセス調査を開始。
  • 2026-11-25：公式ブログで事案を公表し、以下の封じ込め・再発防止策を完了したことを報告：
    • 侵害された GitHub アカウントの無効化、盗難トークンの失効、攻撃者作成アクセスの削除。
    • 影響を受けたバックエンドサービスのクリーンなバージョンへの復旧。
    • 露出の可能性のある全内部認証情報（CI/CD インフラシークレット含む）のローテーション・失効。
    • 招待・アカウント復旧メールの確認コードを 6桁数字から 10文字の英数字へ延長。
    • GitHub・CI/CD・エンドポイントの制御強化と検知ルール追加、外部セキュリティ専門家による検証実施。

4. PiraGo 向け推奨事項

  1. 1Password を利用中のチーム・担当者向け：
    • マスターパスワードや Secret Key の変更は不要です（通常運用を継続）。
    • 1Password からの個別通知メールの有無を確認し、不審な招待・復旧メールや SMS・電話によるフィッシングを厳重に警戒してください。
  2. 自社開発基盤（GitHub・CI/CD）への教訓：
    • 組織全体の GitHub アカウントにフィッシング耐性のある 2FA（パスキー / FIDO2 ハードウェアキー）を必須化。
    • 本番バックエンドへのデプロイ経路で、単一アカウントによる無審査 push を防ぐブランチ保護・必須レビューを徹底。
    • CI/CD の長期固定シークレットを削減し、OIDC による短命トークンおよび環境分離を適用。
