SAP GitHub 開発基盤侵害「Project Granite」（2026年11月）— 従業員トークン悪用とコード署名鍵のローテーション

発生・公開日：2026-11-26（Der Spiegel 報道）· SAP 公式確認 2026-11-27 · 2026-11-28 時点 · 出典：Der Spiegel、BleepingComputer · 状況：GitHub アクセス制限・開発自動化停止・コード署名鍵ローテーション実施済み、顧客データへのアクセス証拠なし。月次レポート：2026年11月 月次レポート。

TL;DR（かんたん解説）： 業務ソフトウェア大手の SAP は、盗まれた従業員の認証トークンを用いて GitHub 上のソフトウェア開発環境へ不正アクセスされたことを認めました（社内緊急対応名「Project Granite」）。

  • 何が起きた？ 攻撃者が従業員の GitHub トークンを悪用してリポジトリにアクセスし、ソースコードの複製および改ざんの可能性が生じたと報じられています。
  • 原因： 従業員の GitHub 認証トークン窃取（一部報道では AI 支援ツールの関与の可能性にも言及）。
  • 現状（11/28時点）： SAP は GitHub アクセスを制限し、自動化された開発ワークフローを一時停止、コード署名鍵をローテーションしました。現時点で顧客の業務データへのアクセス証拠はないとしています。
  • やること： SAP 製品・SDK 利用案件では公式のセキュリティ通知・署名更新を注視。社内では GitHub トークン（PAT/OAuth）の棚卸し、ハードウェア 2FA 徹底、署名鍵の分離を再確認。

1. 概要・影響範囲

  • 対象：GitHub 上でホストされている SAP のソフトウェア開発環境 SAP 確認。
  • 不正行為：攻撃者がソースコードの複製および改ざんを行えた可能性が報じられています 報道。
  • 緊急対応（Project Granite）：SAP は GitHub アクセスを制限し、自動化された開発パイプラインを一時停止したうえで、コード署名鍵（code-signing keys）のローテーションを実施しました 報道。
  • 顧客データ：11月27日時点で、顧客の業務データがアクセスされた証拠はないと SAP は説明しています SAP 確認。

2. 技術的原因・メカニズム

  • 認証経路の悪用：公開されたソフトウェア脆弱性ではなく、従業員の GitHub 認証トークンが狙われました。前日に公表された 1Password の従業員 GitHub 侵害（11/25）と連続しており、開発者アカウント・トークンを標的とした攻撃が続いています。

3. 経緯・復旧

2026/11/28コードの完全性確認と調査を継続中（影響リポジトリ数などの詳細は未公表）。継続監視

4. サプライチェーンへの影響

  • ビルド・リリース改ざんリスク：開発リポジトリへの書き込み権限が奪われた場合、ビルドや署名工程への悪性コード混入リスクが生じるため、SAP は自動化停止とコード署名鍵のローテーションを優先しました。
  • 顧客データ：本番顧客環境への侵入や業務データの流出は確認されていません。

5. PiraGo への推奨事項

  1. 長期 PAT の廃止と GitHub 権限制御：有効期限の短い Fine-grained PAT または GitHub App / OIDC へ移行し、組織メンバー全員にハードウェア 2FA（パスキー/FIDO2）を強制する。
  2. ブランチ保護と署名鍵分離：主要ブランチで必須レビュー（2名以上推奨）・force-push 禁止を有効化し、リリース署名鍵を通常の開発者権限から分離する。
  3. GitHub 監査ログ監視：非公開リポジトリの大量クローン、新規トークン/デプロイ鍵追加、.github/workflows/ 変更をアラート対象にする。
