PHP の CRITICAL 級セキュリティ修正版（2026-11-19）：8.5.13 / 8.4.28 / 8.3.37 / 8.2.36 で 17 件の CVE を修正

2026-11-19 00:30（JST, UTC+9、日付は 11/20）更新：PHP が修正版を公開済みです（GitHub アドバイザリは 14:05〜14:08 UTC に公開）。月次レポート：2026年11月レポート。重大度：緊急（Critical）、CVSS 4.0 最大 9.2。

対応：PHP を 8.2.36 / 8.3.37 / 8.4.28 / 8.5.13（または 8.6.0）へ更新し、PHP-FPM／Apache の再起動とイメージ再ビルドを実施してください。8.1 以前は修正版なし。すぐに更新できない場合は session.upload_progress.enabled を無効化（CVE-2026-115560 のみの暫定策で、他の脆弱性は防げません）。実環境での悪用を報告した情報源は確認できていません。

1. リリース概要

  • バージョン：PHP 8.5.13、8.4.28、8.3.37、8.2.36（セキュリティリリース）と 8.6.0（GA、同日公開）。PHP.net アーカイブによる。GitHub にも対応タグがあります。
  • 規模：GHSA 17 件、うち CVSS 9.2（Critical）が 7 件：エンジン／ext/date／ext/session のメモリ破壊（UAF）4 件、ext/session のデシリアライズ／RCE 2 件、PHP-FPM のリクエストスマグリング 1 件。High 4 件、Moderate 6 件。PHP.net は CRITICAL でも非デフォルト設定または稀な構成が必要としています。
  • CVE-2026-115560 は 10/23 のアドバイザリで「次のリリースで詳細公開」とされていた件です。cve.org：CNA は PHP Group、CVSS 4.0 9.2、CWE-20 / CWE-502。10 月のリリース（8.5.12 など）では修正されていません。

3. CVE-2026-115560（セッション upload progress）

  • タイトル（cve.org）：「Session serializer mismatch can lead to remote code execution」。CVSS 4.0 9.2（AV:N/AC:H/AT:P/PR:N/UI:N、機密性・完全性・可用性への影響大）。
  • 仕組み（概要）：upload progress が有効だと、攻撃者が制御するデータが php_binary または php_serialize ハンドラで書かれるセッションキーに入り得ます。そのセッションが後で php ハンドラで読まれると（session.serialize_handler の実行時変更、またはセッションストアを共有するアプリ間の不一致）、unserialize が実行され、オブジェクト注入、ガジェットチェーンがあれば RCE、あるいはセッション破損／DoS に至ります。
  • 修正版：8.2.36、8.3.37、8.4.28、8.5.13、8.6.0。影響範囲は 8.2.0〜8.2.35、8.3.0〜8.3.36、8.4.0〜8.4.27、8.5.0〜8.5.12。

暫定緩和策（すぐ更新できない場合）

session.upload_progress.enabled = 0
; PHP-FPM pool:
php_admin_value[session.upload_progress.enabled] = 0

php.ini／FPM プール／サーバー設定に記述してワーカーを再起動します。ini_set() や .user.ini は使わないでください。簡易確認：

php -r 'echo ini_get("session.upload_progress.enabled"), PHP_EOL, ini_get("session.serialize_handler"), PHP_EOL;'
grep -RInE "ini_set\(\s*['\"]session\.serialize_handler" --include=*.php .

これは CVE-2026-115560 のみの緩和です。ほかの CVSS 9.2 の脆弱性はバージョン更新でしか解消できません。

4. 対応事項

  1. インターネット公開度で優先順位付け：公開 PHP-FPM／mod_php、multipart アップロードを受けるアプリ、セッションストア（Redis・ファイル・DB）を共有するアプリ。
  2. バージョン更新：8.2.36 / 8.3.37 / 8.4.28 / 8.5.13（準備ができていれば 8.6.0）。php:* イメージは再 pull して php -v を確認してください（公式 Docker イメージの更新時期は未検証）。
  3. 再起動必須：reload では旧バージョンのワーカーが残ります。PHP-FPM／Apache を再起動し、イメージ再ビルドと再デプロイを行ってください。
  4. ディストリ／ホスティング：Ubuntu・Debian・RHEL・Amazon Linux は本家より遅れがちです。確認時点で修正パッケージの状況は未検証（Debian／Red Hat のトラッカーに CVE ページなし）。信頼できるビルドを使うか、待つ間は緩和策を。
  5. サポート終了ブランチ（8.1 以前）：更新計画を立て、当面はアクセス制限、upload progress 無効化、WAF を適用。
  6. 更新後：PHP-FPM のエラーログと不審なセッションを確認し、注入の疑いがあればセッションを失効させます。前回の修正は PHP2Shell（8.5.12 / 8.4.27 / 8.3.36 / 8.2.35）を参照。

5. 未検証の事項

  • 取得した php.net/releases と downloads ページには新バージョンが未反映でした（キャッシュの可能性）。アーカイブと ChangeLog には掲載済みです。
  • 確認時点で NVD に CVE-2026-115560 のレコードはありません（取り込み遅延の可能性）。CVE-2026-48841 の CVSS は未検証です。
  • ディストリと公式 Docker イメージの修正状況は未検証です。
