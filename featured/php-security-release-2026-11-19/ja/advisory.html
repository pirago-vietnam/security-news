PHP の CRITICAL 級セキュリティ修正版（2026-11-19、CVE-2026-115560 を含む）— 事前警告と準備事項

2026-11-19 10:44（JST, UTC+9）時点：修正版は未公開です。月次レポート：2026年11月レポート。重大度：緊急（Critical）（PHP.net の予告による）。Aikido（二次情報）によれば CVE-2026-115560 を含みます。

最初にお読みください：バージョン番号・CVE・技術詳細は未公開です。公開後（日本時間 23:00〜23:30（JST）予定）に本ページを更新します。それまでに稼働中の PHP を棚卸しし、当日中に更新＋再起動できるメンテナンス枠を確保してください。

判明している事項 未確認の事項 CVE-2026-115560 準備事項 参考情報

1. 確認済みの情報

  • 公式予告：PHP.net の 2026-11-18 付 “Upcoming Critical PHP Security Release”。
  • 範囲：サポート中のすべての PHP バージョンに影響する脆弱性を修正するリリース。
  • 重大度：最高は CRITICAL。PHP.net によれば CRITICAL の問題は非デフォルト設定または特殊な構成が前提です。
  • CVE-2026-115560（二次情報）：Aikido によれば今回のリリースに CVE-2026-115560（セッション upload progress 関連、RCE ベクターと説明）が含まれます。確認時点で PHP.net は CVE を未掲載です。
  • 時期：2026年11月19日（木）14:00〜14:30 UTC（日本時間 23:00〜23:30 JST, UTC+9）。技術詳細と修正版は同時に公開予定。

2. 未確認の事項

  • 各ブランチ（8.2 / 8.3 / 8.4 / 8.5 など）の修正版番号、CVSS、および今回の CVE 全リスト（CVE-2026-115560 以外）。Aikido によれば 10月の修正版（8.5.12 / 8.4.27 / 8.3.36 / 8.2.35）にはこの CVE の修正は含まれません。
  • 影響を受けるコンポーネントと「非デフォルト設定」の具体的内容、PoC や実環境での悪用の有無。
  • PHP 8.6.0 GA と同時になるか。PHP.net の 11/12 付エントリに 11/19 の 8.6.0 GA 予定がありますが、これは推測であり未確認です。
  • サポート終了の PHP 8.1 以下は修正版が出ない見込み（ブランチ移行が必要）。

3. CVE-2026-115560（Aikido による情報・PHP.net 未確認）

  • コンポーネント：セッションの upload progress 機能（session.upload_progress）。リモートコード実行（RCE）のベクターと説明されていますが、根本原因は未説明です。
  • 成立条件（両方）：(1) session.serialize_handler が php_binary または php_serialize で、アプリが session_start() 前に ini_set() で php に切り替える。(2) セッション upload progress が有効（PHP のデフォルトは有効）。
  • 経緯：PHP は 2026-10-23 に情報提供アドバイザリを公開（PHP2Shell の後）、完全な公開は次回リリースと予告。8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 ではこの CVE は修正されません。
  • 未確認：CVSS、ブランチ別修正版、PoC・悪用状況（PHP は深刻度スコアを未公表）。

暫定緩和（今すぐ可能）

  • システムレベルの設定（php.ini、PHP-FPM プール、サーバー設定）で upload progress を無効化し、ワーカーを再起動。リクエスト解析前に有効である必要があるため ini_set() や .user.ini は使用しないでください： 
    session.upload_progress.enabled = 0
; PHP-FPM pool:
php_admin_value[session.upload_progress.enabled] = 0
  • コード確認：実行時に session.serialize_handler を php に切り替えないアプリは条件(1)を満たさず、upload progress を有効のままにできます。 
    php -r 'echo ini_get("session.upload_progress.enabled"), PHP_EOL, ini_get("session.serialize_handler"), PHP_EOL;'
grep -RInE "ini_set\(\s*['\"]session\.serialize_handler" --include=*.php .
  • PHP.net の公表後：PHP を修正版へ更新、再起動、イメージ再ビルド。

4. 本日中に準備すること

  1. PHP の棚卸し：PHP が動くホスト、コンテナ、イメージ、マネージドホスティングを洗い出し、ブランチ（8.1 以下／8.2〜8.5）と SAPI（mod_php、PHP-FPM、FrankenPHP、CLI）を記録。
  2. インターネット公開面の特定：外部からアクセス可能な PHP サービスと、php.ini／FPM プールのカスタム設定を確認（CRITICAL は非デフォルト設定が条件の可能性）。
  3. メンテナンス枠の確保：更新＋再起動（reload では旧プロセスは置き換わりません）、Docker イメージの再ビルドと CI/CD の準備。
  4. ディストリビューション／ベンダー修正の確認：Ubuntu、Debian、RHEL、Amazon Linux、php:* イメージ、ホスティング事業者は本家より数時間〜数日遅れることがあります。
  5. サポート終了ブランチ（8.1 以下）：移行計画を立て、当面はアクセス制限と WAF を適用。
  6. 監視：23:00（JST）以降に php.net/archive と ChangeLog-8 を確認。前回の修正は PHP2Shell（8.5.12 / 8.4.27 / 8.3.36 / 8.2.35）を参照。
